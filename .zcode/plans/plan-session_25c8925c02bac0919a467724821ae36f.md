## Four workstreams, in execution order

### 1. Capture latency fix (fast in every app)

Root cause (verified by reading the pipeline): the clipboard focus-window read retries only ~220 ms and then gives up; TikTok/Instagram/Twitter write the link late (async short-link work), so the only read misses, and the click-event fallback is delayed 350 ms and *dropped* if a read ran in the prior 600 ms. Browsers write instantly, hence their speed.

Changes in `ClipboardFocusWindow.kt` + `ClipboardMonitor.kt`:
- **Extended retry window**: after a failed direct read, keep the focus window and poll with growing intervals (40 / 100 / 250 / 500 / 1000 / 2000 / 3000 ms — ~7 s total coverage) instead of giving up after 220 ms. Release the window as soon as a read succeeds or the window expires. Extract the cadence into a pure, unit-testable helper (`CaptureRetryCadence`).
- **Stop dropping reads**: forced reads (clipboard-change listener) are never dropped by the 600 ms gate; while a focus read is in flight, a new request queues as a follow-up instead of being discarded.
- **Click delay 350 → 150 ms** (the long retry window makes a long pre-delay unnecessary).
- **Diagnostics**: log the three currently-silent drop points (`onInteraction` fired, read skipped by interval gate, focus read ended with null) plus per-read duration, so per-app behavior is verifiable in logcat on your phone.
- Verify on-device with the connected Xiaomi: copy from Instagram/Twitter, read `AFTERLATER-DETECT` timestamps before/after.

### 3. Smart sorting engine (daily batch + archive)

New pure, heavily tested domain object `domain/review/SmartSorter.kt`:
- **Score per entry**: deadline urgency (soonest `expiresAt` first — expired entries already drop out of eligibility), never-opened boost (`lastReviewedAt == null`), age boost (older `savedAt` first). Deterministic tie-break by id. Existing domain-diversity selection in `ReviewScheduler.selectDailyBatch` is kept and fed by the new ranking.
- **Daily batch**: `ReviewScheduler` refactored to rank via SmartSorter (existing tests updated where ordering legitimately changes; all invariants kept: cap 5, diversity, expired exclusion).
- **Archive**: new default sort option **SMART** in the archive (alongside Newest/Oldest/Last reviewed) that ranks the fetched list in memory through SmartSorter — no new SQL, no schema change (the archive query already returns the full filtered list).
- Unit tests for scoring order, deadline clamps, and the batch invariants.

### 4. Auto-categorization — last, as requested

**Honest difficulty: easy-to-moderate.** Not worth ML: a rules engine — a domain map (github.com/stackoverflow → coding; dribbble/behance → design; amazon/aliexpress → offer; openai/huggingface → AI; …) plus a keyword lexicon over the title/description that MetadataWorker *already fetches* — covers the obvious cases well and ambiguous ones gracefully (no guess → no tag).

Storage costs **zero schema change**: a detected category is just a **tag** in the existing `tags` system — auto-applied at capture (or pre-selected in the card's TAG IT? stage), instantly filterable via the archive's TAG filter, and later usable as a variety signal in SmartSorter. Effort: roughly one focused session including tests. Planned only after 1–3 ship and are verified on-device.
